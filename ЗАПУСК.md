# Гайд по локальному запуску

Короткая инструкция, как поднять проект на своей машине после внесённых правок.

---

## Что было исправлено (кратко, чтобы понимать, почему нужен `.env`)

- Убраны хардкод-фолбэки для `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, `DATABASE_URL`.
  Теперь бэкенд **не стартует**, если этих переменных нет в окружении и каждый
  из секретов короче 32 символов. Это правильно и безопасно, но значит — не забудьте
  скопировать `.env.example` и заполнить реальные значения.
- Добавлены `helmet`, rate-limit (`@nestjs/throttler`), body size limit 1 MB,
  Swagger выключен в production.
- Добавлены индексы в Prisma-схему — перед первым запуском нужна миграция.
- Усилена политика пароля при регистрации (заглавная, строчная, цифра, спецсимвол).

## Вариант A. Запуск в Docker (рекомендуется — один клик)

Требования: Docker Desktop, Git.

```bash
# 1. Клонируем и заходим в проект
cd VKR_CLAUDE

# 2. Создаём .env в корне репозитория
cp .env.example .env

# 3. Генерируем два JWT-секрета (по ≥32 символа каждый)
#    На Linux / macOS / WSL:
openssl rand -base64 48
openssl rand -base64 48
#    На Windows PowerShell:
#    [Convert]::ToBase64String((1..48 | % { Get-Random -Max 256 }))

# Скопируйте эти значения в .env → JWT_ACCESS_SECRET и JWT_REFRESH_SECRET.
# Также задайте свой POSTGRES_PASSWORD.

# 4. Поднимаем стек
docker compose up -d --build

# 5. Применяем миграции Prisma внутри контейнера бэкенда
docker compose exec backend npx prisma migrate deploy
docker compose exec backend npm run prisma:seed   # если есть сид

# 6. Открываем в браузере
# Frontend (через nginx):   http://localhost
# Backend напрямую:          http://localhost:3000
# Swagger (только dev):      http://localhost:3000/api/docs   (выключен в production)
```

Остановить: `docker compose down`. Очистить данные БД: `docker compose down -v`.

## Вариант B. Запуск без Docker (нужен локальный Postgres)

Требования: Node.js 20+, npm, PostgreSQL 16, Git.

### 1. Postgres

Создайте БД и пользователя — например, через `psql`:

```sql
CREATE USER prepai WITH PASSWORD 'choose_a_strong_password';
CREATE DATABASE prepai OWNER prepai;
```

### 2. Backend

```bash
cd backend
cp .env.example .env
```

Откройте `backend/.env` и заполните:

```
DATABASE_URL="postgresql://prepai:choose_a_strong_password@localhost:5432/prepai"
JWT_ACCESS_SECRET="...сгенерированная_строка_≥32_символов..."
JWT_REFRESH_SECRET="...другая_строка_≥32_символов..."
```

Сгенерировать секреты (любой один):

```bash
openssl rand -base64 48
node -e "console.log(require('crypto').randomBytes(48).toString('base64'))"
```

Установка и первый запуск:

```bash
npm install
npx prisma generate
npx prisma migrate deploy        # применит все существующие миграции
# если в schema.prisma появились новые поля/индексы и миграций ещё нет:
npx prisma migrate dev --name add_indexes

# (опционально) наполняем базу материалами и вопросами
npm run prisma:seed

# запускаем в dev-режиме с горячей перезагрузкой
npm run start:dev
```

Бэкенд поднимется на `http://localhost:3000`, Swagger — `http://localhost:3000/api/docs`.

### 3. Frontend

В новом терминале:

```bash
cd frontend
cp .env.example .env            # VITE_API_URL=http://localhost:3000 — по умолчанию уже правильный
npm install
npm run dev
```

Откройте `http://localhost:5173`.

## Частые проблемы

**`Error: JWT_ACCESS_SECRET must be set in environment and be at least 32 characters long`**
Вы забыли скопировать `.env` или секрет меньше 32 символов. Сгенерируйте заново
командой `openssl rand -base64 48`.

**`Error: DATABASE_URL must be set in environment`**
Нет `.env` в папке `backend/` (или в корне, если запускаете через Docker Compose).

**`P1001: Can't reach database server`**
Postgres не запущен / неверный хост. В Docker хост — `postgres`,
локально — `localhost`.

**`Prisma Client is not generated`**
Запустите `npx prisma generate` в `backend/`.

**`Cannot find module '@rollup/rollup-linux-x64-gnu'` во фронте**
Баг npm с optional dependencies. Удалите `node_modules` и `package-lock.json`
во `frontend/`, затем `npm install` заново.

**Регистрация возвращает 400 `Пароль должен содержать хотя бы одну заглавную букву`**
Теперь пароль требует: минимум 8 символов, заглавную и строчную буквы,
цифру и спецсимвол. Пример валидного: `MyPass123!`.

## Проверка, что всё работает

1. Открыть `http://localhost:5173` — видна лендинг-страница.
2. Зарегистрироваться (`email`, пароль `MyPass123!`) → должно пройти три шага и
   открыть главную.
3. Зайти в «Тесты», пройти любой тест до конца → на странице результатов видно
   правильные/неправильные ответы.
4. Открыть `http://localhost:3000/api/docs` — Swagger отображает эндпоинты.
5. Перелогиниться — куки `access_token` и `refresh_token` стоят как `httpOnly`
   (видно в DevTools → Application → Cookies).

Если всё выше работает — проект поднят корректно.
